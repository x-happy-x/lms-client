# Вход через Account (LMSC-9 / ACC-22)

Нужны обновлённые Account (ACC-22), lms-client (LMSC-9), расширение **0.6.0**.
Нода продолжает использовать отдельный HMAC между роутером и агентом; её
пользовательские пароли не меняются.

На Account задайте точный публичный origin веб-интерфейса:

```sh
LMS_CLIENT_ORIGINS=https://lms.example.org
```

На роутере, в окружении процесса routerd:

```sh
ROUTERD_ACCOUNT_ORIGIN=https://account.crubs.crazedns.ru
ROUTERD_PUBLIC_ORIGIN=https://lms.example.org
```

Публичный LMS origin должен открываться в браузере через HTTPS. Account должен
быть доступен по HTTPS и из браузера, и с роутера. Невалидный origin блокирует
API с 503. Без `ROUTERD_ACCOUNT_ORIGIN` сохраняется существующий LAN-режим;
публичное включение авторизации требует выставить эту переменную. В этой
задаче новая авторизация на живых сервисах не включалась.

Веб-интерфейс при 401 открывает `/auth/login`, ставит HttpOnly state cookie и
переходит в Account. После подтверждения одноразовый код меняется на токен с
PKCE S256, и роутер сохраняет его в HttpOnly Secure SameSite=Lax cookie.
Возврат разрешён только на относительный путь текущего LMS.

В расширении укажите LMS и Account, нажмите **Войти**. Откроется системное
окно `chrome.identity.launchWebAuthFlow`. Пароль вводится только на сайте
Account. Разрешение действует 30 дней только для `lms_node`. Выход отзывает
токен; отозвать его также можно в профиле Account.

Токен расширения хранится в `chrome.storage.local` с доступом
`TRUSTED_CONTEXTS`, не синхронизируется и не выдаётся content scripts. Он
привязан к точным адресам LMS и Account; на другой адрес не отправляется.
При 401 сеанс и кеш извлечения видео очищаются. Смена пользователя также
очищает кеш. Серверные редиректы API с Bearer не выполняются.

`manifest.key` фиксирует ID `acehojonpkjinnelheepaajgjbeejbff`; это публичный
ключ без приватной части. Сборка до 0.6 без key могла иметь другой ID:
установите новую папку распакованного расширения, заново укажите адреса и
выполните вход. Callback Account задан этим ID в `lms-extension-client.json`.
Для сборки с другим ID измените allowlist `LMS_EXTENSION_IDS` на Account.

Каждый защищённый запрос проверяет токен и актуальную роль в Account:

| Роль | Доступ |
| --- | --- |
| viewer | Чтение, preflight, поиск видео и оценка места |
| editor | Также создание, отмена, перемещение и удаление заданий/файлов |
| admin | Также изменение нод и профилей |

При недоступном Account API возвращает 503, доступ не открывается. Снятие
роли/блокировка/отзыв прекращает доступ без кеша проверки токена. Изменяющие
запросы с cookie требуют Origin ровно публичного LMS; расширение использует
Bearer. Старые LAN-клиенты после включения режима должны передавать такой
же scoped Bearer; одного HTTP Basic за внешним прокси недостаточно.

Проверка: Account `npm test`, расширение `npm test`, роутер `go test ./...`,
веб-интерфейс `npm run build` и `npx tsc --noEmit`. Реальный интерактивный
вход пользователя выполняется после выкладки Account и routerd с этими
параметрами. Тесты проверяют протокол с локальными Account fixtures.
