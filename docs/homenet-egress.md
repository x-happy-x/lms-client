# HomeNet и маршрут загрузки (LMSC-17)

## Что подтверждено

Загрузку выполняет нода, а не браузер или роутер LMS. Адрес ноды в API LMS
не доказывает маршрут её исходящего соединения. HomeNet использует Mihomo;
`GET /api/mihomo/connections` содержит `metadata.sourceIP`, `metadata.host`,
`metadata.destinationIP`, `metadata.destinationPort`, `chains`, `rule` и
`rulePayload`. Только совпавшее соединение подтверждает текущий путь.

Проверка 11 ноября 2026 без изменения конфигурации: у HomeApps
`192.168.99.33` одновременно наблюдались три соединения с разными цепочками.
Режим `rule`. Значит единственного «VPN ноды» в этом режиме нет.
Отсутствие совпадения означает «маршрут не подтверждён», а не DIRECT.
После перехода сайта на другой CDN совпадение по исходному домену перестаёт
быть доказательством маршрута медиафайла.

Существующие интерфейсы HomeNet:

- `GET /api/mihomo/configs`, `/proxies`, `/connections` — фактическое состояние.
- `PUT /api/mihomo/proxies/{group}` с `{name}` — **общая** группа маршрутизации.
  Изменение затрагивает остальные устройства и не подходит для выбора VPN
  одного задания.
- `GET /api/core/devices` — список устройств. Запись меняет описание хоста
  Keenetic, универсального API выбора маршрута устройства нет.
- В настройках маршрутизации есть адресные правила торрентов; универсального
  предсказателя правил/маршрута ещё не существует.

У действующего общего HTTP/mixed/SOCKS-порта нет аутентификации. Его нельзя
выдавать пользователю как выделенный защищённый маршрут задания.

## Выбор для одного задания

Mihomo уже поддерживает HTTP listener с `proxy: <имя прокси или группы>` и
собственными `users`. Это фиксирует SpecialProxy только для соединений,
пришедших на этот listener. Не требует изменения общей группы.

HomeNet должен владеть реестром разрешённых listener-ов:

```yaml
listeners:
  - name: lms-egress-eu
    type: http
    listen: <адрес LAN>
    port: <свободный выделенный порт>
    proxy: <разрешённый выход или группа>
    users:
      - username: <отдельная учётная запись ноды>
        password: <секрет вне репозитория>
```

Доступ ограничивается исходящими IP нод в firewall. Пароли и endpoint-ы
хранятся на серверах и передаются при установке по защищённому каналу;
в API браузеру и Android выдаются только `id`, подпись, возможности и статус.
Проверка тестового listener-а делается в отдельной фикстуре. Создание реального
listener-а или reload Mihomo — отдельная операция деплоя, не часть UI-теста.

Нода хранит разрешённое соответствие `routeId -> HTTP proxy endpoint` и принимает
только `networkRouteId`. HTTP proxy совместим с Java HttpClient, `yt-dlp --proxy`,
`aria2c --all-proxy` и FFmpeg `-http_proxy`. SOCKS нельзя обещать для всех этих
движков одним переключателем. Прокси применяется также к разрешению URL,
поиску плейлиста, метаданным и просмотру; ключи кешей включают routeId.
Неизвестный routeId и неподдерживаемый движок отклоняются до запуска задания.
Команды диагностики и сообщения об ошибке скрывают proxy userinfo.

Первый вариант меняет маршрут **нового** задания. Для существующего нужна
отдельная явная операция остановки/возобновления; нельзя молча менять путь
среди уже открытых соединений и показывать прежний маршрут подтверждённым.

## Предлагаемый контракт

Роутер: `GET /api/ui/network/routes?nodeId=<id>&url=<HTTP(S)>`.

```json
{
  "enabled": true,
  "nodeId": "homeapps",
  "canSelect": true,
  "planned": {"state": "automatic", "label": "Правила HomeNet", "scope": "download"},
  "routes": [
    {"id": "homenet-eu", "label": "HomeNet · Европа", "available": true,
     "supportedTypes": ["DIRECT", "YTDLP", "ARIA2C"], "scope": "download"}
  ],
  "observed": [
    {"host": "media.example.test", "chains": ["Выход EU", "AUTO"],
     "rule": "DomainSuffix", "observedAt": "2026-11-11T10:00:00Z"}
  ],
  "checkedAt": "2026-11-11T10:00:00Z"
}
```

`planned.state`: `configured` для явно выбранного listener-а, `automatic` для
правил HomeNet, `unknown` при отсутствии данных. `observed` содержит только
доказанные совпадения, никогда прогноз. Подпись группы — ещё не название
конечного выхода; для группы конечный путь может измениться после создания.

Создание задания: необязательный `networkRouteId`. Пустой идентификатор сохраняет
обычное поведение. Preflight сообщает `networkRoutesSupported`. Статус задания
возвращает выбранный routeId/label и наблюдаемый путь раздельно. Старое задание
без выбранного routeId не получает выдуманный VPN из текущего состояния группы.

## Авторизация интеграции

Существующий HomeNet Core требует собственного администратора Account.
Токен с app=`lms_node` не является токеном HomeNet; cookies браузера не копируются.

Образец уже есть: `backend/internal/core/pc_power.go` HomeNet. Точный endpoint,
собственный файл `credentials/lms-egress.token`, constant-time Bearer-проверка,
запрет Origin/cross-site и фиксированное направление на worker VPN. Нужен такой
же ограниченный endpoint `/api/lms/egress`: только чтение разрешённых listener-ов
и соединений по заранее разрешённому IP ноды. Не общий reverse proxy Mihomo,
не полный worker token и не API изменения mode/configs/proxies.

Настройки LMS указывают origin HomeNet и token-file; API отдаёт клиентам лишь
факт настройки. Роль LMS viewer может читать маршруты собственных загрузок;
создание задания с выбранным маршрутом использует обычные права редактора.
Настройка интеграции/реестра требует администратора. Нельзя принимать от клиента
произвольный адрес прокси, токен HomeNet или IP чужого устройства.

Реализация затрагивает отдельные задачи в LMS (нода), NPM (ограниченный контракт
HomeNet) и LMSC-17 (прокси/данные/веб-интерфейс). Android использует тот же
роутерный контракт. Ни один живой маршрут при исследовании не менялся.
